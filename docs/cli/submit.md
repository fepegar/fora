# fora submit

Submit a training job to Azure ML. Handles code upload, environment creation, and job orchestration.

## Usage

```bash
fora submit [OPTIONS] --subscription <ID> --resource-group <NAME> --workspace <NAME> \
    --experiment <NAME> --cluster <NAME> [-- <ARGS>...]
```

## Required options

| Flag | Short | Description |
|------|-------|-------------|
| `--subscription <ID>` | `-s` | Azure subscription ID |
| `--resource-group <NAME>` | `-r` | Azure resource group name |
| `--workspace <NAME>` | `-w` | Azure ML workspace name |
| `--experiment <NAME>` | `-e` | Experiment name to submit the job under |
| `--cluster <NAME>` | `-c` | Azure ML compute cluster to run the job on |

## Optional flags

| Flag | Default | Description |
|------|---------|-------------|
| `--name <NAME>` | Auto-generated | Display name for the job |
| `--source <PATH>` | Current directory | Path to the source code directory to upload |
| `--command-prefix <CMD>` | `uv run` | Command prefix prepended to the job command |
| `--executable <CMD>` | `python` | Executable to use for the job |
| `--set <NAME=VALUE>` | — | Environment variable (repeatable) |
| `--mount <SPEC>` | — | Mount an input (repeatable, see [Input mounts](#input-mounts)) |

## Environment options

| Flag | Default | Description |
|------|---------|-------------|
| `--env-type <TYPE>` | `uv` | Environment type: `uv` or `docker` |
| `--base-docker-image <IMAGE>` | — | Base Docker image for the environment |
| `--auto-rebuild` | `true` | Automatically rebuild when the base image changes |

## UV options

These options apply when `--env-type uv` is used (the default):

| Flag | Description |
|------|-------------|
| `--project-dir <PATH>` | Path to the uv project directory (defaults to `--source` directory) |
| `--uv-extra <EXTRA>` | Extra dependency group to include (repeatable) |
| `--uv-group <GROUP>` | Dependency group to include (repeatable) |

## Trailing arguments

Everything after `--` is passed as arguments to your script:

```bash
fora submit [OPTIONS] -- train.py --epochs 10 --lr 0.001
```

The final command executed on the cluster is:

```
<command-prefix> <executable> <args...>
```

For example, with defaults: `uv run python train.py --epochs 10 --lr 0.001`

## Input mounts

The `--mount` flag supports two formats:

### Data asset

Mount a registered data asset:

```
--mount alias=data_asset_name:version
```

Version is optional and defaults to `latest`:

```
--mount training_data=my-dataset:2
--mount training_data=my-dataset
```

### Datastore path

Mount a path from a datastore:

```
--mount alias=datastore_name/path/in/datastore
```

## How it works

When you run `fora submit`, the following happens concurrently:

1. **Code upload** — The source directory is walked (respecting `.gitignore` via `.amlignore`), and files are uploaded to Azure Blob Storage.
2. **Environment creation** — A deterministic environment name is generated by hashing `pyproject.toml`, `uv.lock`, `.python-version`, and configuration with BLAKE3. If an environment with that hash already exists, it is reused.

Once both complete, a `CommandJob` is submitted to Azure ML.

## Examples

Submit a basic training job:

```bash
fora submit \
  -s 00000000-0000-0000-0000-000000000000 \
  -r my-resource-group \
  -w my-workspace \
  -e my-experiment \
  -c gpu-cluster \
  -- train.py --epochs 10
```

Submit with a custom source directory and environment variables:

```bash
fora submit \
  -s 00000000-0000-0000-0000-000000000000 \
  -r my-resource-group \
  -w my-workspace \
  -e my-experiment \
  -c gpu-cluster \
  --source ./my-project \
  --set WANDB_API_KEY=abc123 \
  --set CUDA_VISIBLE_DEVICES=0,1 \
  -- train.py
```

Submit with data mounts:

```bash
fora submit \
  -s 00000000-0000-0000-0000-000000000000 \
  -r my-resource-group \
  -w my-workspace \
  -e my-experiment \
  -c gpu-cluster \
  --mount training_data=my-dataset:2 \
  --mount raw_data=blobstore/data/raw \
  -- train.py
```
